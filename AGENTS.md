# Инструкции для помощников по разработке

## Навигация

- Серверная часть: `backend/app/`; точка входа — `app.main:app`.
- HTTP API: `backend/app/api/`; схемы — `backend/app/schemas/`.
- Модели и миграции: `backend/app/models/`, `backend/alembic/versions/`.
- Фоновая обработка документов: `backend/worker/celery_app.py`, `backend/app/services/ingestion/`.
- Поиск и чат: `backend/app/services/retrieval/`, `backend/app/services/chat/`.
- Клиентская часть: `frontend/src/`; App Router — `frontend/src/app/`.
- Документация: начните с `docs/README.md`.

## Неподлежащие нарушению границы

- `organization_id` берётся только из аутентифицированной сессии или доверенной записи БД.
- Векторный и полнотекстовый поиск фильтруются по `organization_id` и `access_roles` до RRF,
  повторного ранжирования и передачи контекста языковой модели.
- Не считайте RLS активной защитой, если среда выполнения подключается к PostgreSQL от имени суперпользователя без
  `DOCWISE_RLS_SESSION_ROLE`.
- Не передавайте содержимое недоступных фрагментов в запрос к языковой модели, кэш, журнал аудита или текст ошибки.
- Изменение ORM-моделей требует новой Alembic-миграции; существующие миграции не переписываются.
- Изменения кода обработки документов требуют перезапуска `celery-worker`.

## Проверки

```bash
make lint
make test-smoke
make test
make typecheck
make test-frontend
```

Команды `make test*` требуют запущенной серверной части в Compose. `make lint` использует
`backend/.venv`, проверки клиентской части — установленные `frontend/node_modules`.
Изменения поиска, запроса к языковой модели, ACL или разбиения текста на фрагменты дополнительно проверяйте через
`make eval-retrieval` или `make eval` при наличии нужной инфраструктуры и ключа LLM.

## Документация и безопасность

- Проверяйте утверждения по коду, миграциям, тестам и конфигурации.
- Пишите пояснительный текст естественным русским языком. Оставляйте без перевода точные имена
  символов, API, переменных, команд, пакетов и моделей. Названия метрик переводите в пояснениях;
  оригинальную форму приводите рядом, если она нужна для точной идентификации. Для терминов
  используйте согласованные русские варианты из [указателя документации](docs/README.md#язык-и-термины).
- Не включайте секреты, дампы, документы пользователей и содержимое `.env`.
- При изменении маршрутов, конфигурации или операций синхронизируйте соответствующий документ
  и `docs/maintenance/documentation-audit.md`.
