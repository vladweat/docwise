# API документов

Все маршруты ограничены текущей организацией. `admin` и `manager` управляют базой знаний;
серверная часть повторно проверяет права независимо от интерфейса.

## Варианты доступа для интерфейса

```http
GET /api/v1/documents/access-options
```

Доступен ролям `admin` и `manager`. Возвращает фиксированный набор ролей организации (`admin`, `manager`, `employee`)
и уникальные подразделения участников текущей организации. `organization_id` берётся из текущей сессии,
а не из строки запроса или тела запроса.

## Загрузка

```http
POST /api/v1/documents/upload
Content-Type: multipart/form-data
```

Поля: `file` (PDF/DOCX) и `access_roles` (повторяющееся поле или массив JSON).
Успешный ответ — `201`, документ получает состояние `pending`; Celery обрабатывает его в фоне.
Поле обязательно. `all` означает всю организацию и не может сочетаться с другими тегами. Без `all` несколько
ролей и подразделений объединяются по логическому ИЛИ: достаточно совпадения с одним тегом. Один и тот же разбор
прав применяется при загрузке и `PATCH`; сочетание `all` с другими тегами отклоняется с `400`.

| Условие | Результат |
| --- | --- |
| Файл больше `UPLOAD_MAX_BYTES` (по умолчанию 50 MiB) | `413` |
| Неподдерживаемый формат | `400` |
| Такой SHA-256 уже загружен в эту организацию | `409 resource.conflict`, без раскрытия существующей записи |
| Превышена квота страниц | `402 billing.payment_required`, Celery не вызывается |

Для PDF квота считается по страницам; для DOCX — по логическим разделам. Разбор файла не выполняется внутри обработчика загрузки.

## Список и статус

```http
GET /api/v1/documents?limit=20&offset=0&status=ready
GET /api/v1/documents/{id}/status
```

`limit`: 1–100 (по умолчанию 20); `offset`: от 0. Возвращаются только документы текущей организации,
доступные текущей роли. В ответ входят `pending | processing | ready | failed`, `stage` и безопасное описание
ошибки `last_error` для состояния `failed`.

## Изменение доступа

```http
PATCH /api/v1/documents/{id}
Content-Type: application/json
```

Тело: `{ "access_roles": ["hr", "admin"] }`. В одной транзакции обновляются документ и все его текстовые
фрагменты; повторная индексация не требуется. Пустой список — `422`; отсутствующая запись — `404 resource.not_found`.

## Удаление и просмотр оригинала

```http
DELETE /api/v1/documents/{id}
GET /api/v1/documents/{id}/raw
```

`DELETE` возвращает `204`, удаляет строки документа и фрагментов и записывает строку в очередь отложенного удаления
`storage_deletions` в той же транзакции. Фоновый обработчик повторяет удаление закрытого объекта S3; ошибки остаются в очереди.

`raw` возвращает PDF или DOCX только после проверки организации и ACL. Постоянная публичная ссылка на объект хранилища не выдаётся.

Ошибки и общий формат ответов: [обзор API](overview.md). Обработка документов описана в [pipeline/ingestion.md](../../pipeline/ingestion.md).
