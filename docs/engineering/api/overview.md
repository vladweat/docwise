# Общие ответы API

Этот файл дополняет [главную страницу API](../api.md). Точные маршруты и схемы берутся из
`backend/app/api/` и `backend/app/schemas/`; OpenAPI `/docs` включён только вне рабочей среды.

## HTTP-ошибки

Все HTTP-ошибки используют единый формат:

```json
{
  "error": {
    "code": "request.validation",
    "message": "Request validation failed",
    "details": { "issues": [{ "location": ["body", "query"], "code": "missing" }] }
  }
}
```

`details.issues` содержат расположение поля и код проверки, но не отправленные значения или текст исключения.
Необработанная ошибка возвращает общий `500`. Клиентская часть сохраняет совместимость со старым форматом
`detail` на время перехода.

Ошибки после начала потока используют [формат SSE чата](chat.md), а не общий формат HTTP-ошибок.

## Проверки состояния сервиса

| Маршрут | Что проверяет | Ответ |
| --- | --- | --- |
| `GET /` | Метаданные службы; `/docs` будет `null` в рабочей среде | `200` |
| `GET /health` | Только работоспособность процесса | `200`, пока процесс отвечает |
| `GET /ready` | PostgreSQL/pgvector, Redis, хранилище S3 и обработчик оплаты | `200` — готов; `503` — частичная недоступность |

`BILLING_PROVIDER=dev` отображается как `dev`, а не как ошибка. Если Stripe не настроен, `/ready` сообщает о частичной недоступности.

## Общие правила входа и изоляции организаций

- Сессия в cookie требуется на всех маршрутах API, кроме явно открытых маршрутов входа, регистрации, Google, SSO и вебхука Stripe.
- Первичная регистрация создаёт пользователя, организацию и членство с ролью `admin`; приглашение добавляет пользователя в существующую организацию.
- `organization_id`, `org_id`, `access_roles`, `document_ids` и `user_id` из тела запроса чата или поиска не дают полномочий.
- API не подтверждает наличие чужого документа или сессии: он возвращает тот же `404`, что и для отсутствующей записи.

Подробнее: [вход и ACL](../../platform/auth.md), [изоляция организаций](../../platform/tenancy.md).
