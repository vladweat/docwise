# Диагностика выбора контекста по rank

**Дата:** 2026-10-31 · **Профиль:** `multilingual-compact` · **threshold:** `0.01` · **Top-K:** `4`

Источник: [sanitized case diagnostics](rag_quality_candidate_001_instrumented_case_diagnostics.json),
dataset SHA-256 `04e8b54242c9951607330e39030a6a461f1398c9eab50d4c33e066aacf225f84`.
Отчёт содержит только агрегированные значения; вопросы, ответы и passage text сюда не копировались.

## Что измерено

В полном прогоне 132 кейсов у context-precision judge сохранены бинарные verdicts для каждого
возвращённого контекста в исходном порядке. Это позволяет пересчитать retrieval-side метрики для
Top-1…Top-4 на тех же результатах reranker без нового rerank. Для retrieval/context метрик доступны
84 из 85 positive кейсов: у одного кейса generation/judge завершился ошибкой, его verdicts отсутствуют.
Точный target section размечен для 52 кейсов.

| Selection | Context Precision | Доля сохранённых релевантных контекстов из Top-4 | Exact target section |
| --- | ---: | ---: | ---: |
| Top-1 | 0.917 (`n=84`) | 0.698 | 40/52 |
| Top-2 | 0.952 (`n=84`) | 0.913 | 49/52 |
| Top-3 | 0.943 (`n=84`) | 0.948 | 49/52 |
| Top-4 | 0.940 (`n=84`) | 1.000 | 51/52 |

Judge отмечал контексты релевантными с частотой `0.917` на rank 1 (`n=84`), `0.500` на rank 2
(`n=68`), `0.163` на rank 3 (`n=49`) и `0.278` на rank 4 (`n=36`). Поэтому добавление контекстов
после второго ранга в этом кандидате чаще снижало rank-weighted precision, чем добавляло полезные
фрагменты.

## Сравнение с отсечкой по reranker score

Score threshold пересчитан из тех же отсортированных списков. Списки score монотонны, поэтому
порог оставляет префикс исходного Top-4. Context Precision усредняется только по кейсам, где после
отсечки остался хотя бы один контекст; доля сохранённых релевантных контекстов считается от всех
judge-relevant контекстов исходного Top-4.

| Threshold | Кейсы с контекстом | Среднее число контекстов | Context Precision | Доля релевантных контекстов | Exact target section |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0.01 | 84/84 | 2.821 | 0.940 | 1.000 | 51/52 |
| 0.03 | 84/84 | 2.524 | 0.937 | 0.969 | 49/52 |
| 0.05 | 83/84 | 2.357 | 0.932 | 0.938 | 47/52 |
| 0.10 | 82/84 | 2.012 | 0.930 | 0.891 | 46/52 |
| 0.25 | 82/84 | 1.738 | 0.921 | 0.849 | 44/52 |

В этом запуске score threshold выше `0.01` ухудшил Context Precision и recall. Top-2 rank cap дал
наибольший Context Precision из проверенных вариантов, но всё ещё ниже gate `0.975` и потерял две
точные секции относительно Top-4. Он не проверяет target-document hit: в артефакте сохранён только
счётчик target-документов, без per-rank target-document flags.

## Ограничения и решение

Это повторное использование verdicts, полученных на Top-4 контекстах. Оно измеряет релевантность и
точную секцию, но не показывает, как другой набор контекстов изменил бы сгенерированный ответ,
Answer Relevance, Faithfulness или citation support. Для этого потребуется отдельный end-to-end
прогон с выбранным cap.

Top-2 — диагностический кандидат, не принятая настройка: Context Precision улучшается лишь на
`0.013`, остаётся ниже порога, а exact-section hit падает `51/52 → 49/52`. Target-document hit
после ограничения rank по текущему артефакту неизвестен. Production threshold и Top-K остаются без
изменений. Перед end-to-end кандидатом стоит дополнить rank labels per-rank target-document
boolean и проверить документный recall; если он сохраняется, сравнить Top-2 end-to-end с Top-4
на тех же 132 кейсах.
